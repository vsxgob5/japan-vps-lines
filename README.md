## 先把两件事分开：延迟低 ≠ 路由好

延迟是物理距离决定的。东京到中国大陆的往返时间，正常范围在 50–90ms，这是电信 CN2 GIA 线路下多个第三方整理的测试区间；换成国际普通线路，即使机房一模一样，晚高峰也会因为绕路、拥塞而出现明显抖动。

"绕路"这个词不是修辞。日本 Tier 1 国际线路的联通方向就有绕美走 Lumen 的情况，数据包先跨太平洋到美国再回来，延迟直接翻倍。同一个东京机房，两台机器的体验可以完全不一样。

所以选日本云服务器时，第一个要问的问题不是"CPU 几核"，而是"回程走哪条线"。

DMIT 东京机房目前的产品线正好把这三档覆盖全了，用它当参照物比较直观：

**Premium（代号 Pro）**——回程电信 CN2 GIA，联通走 AS9929/AS10099 精品网，移动走 CMI。三网都有优化，KVM 虚拟化，1Gbps 端口，标配 1 个 IPv4 加 1 组 /64 IPv6，硬件是 AMD EPYC 7003 系列。这是给国内用户访问做深度优化的那一档：建站、跨境业务后台、远程办公，只要访问者主要在中国大陆，就别在这上面省钱。
